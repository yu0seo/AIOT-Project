# 지속 분석 서비스 계약

- 입력은 기존 Supabase Storage 버킷의 한 prefix 안에 있는 `000000000000.ts` 형태의 서로 다른 연속 파일 15개다. 최초 시작은 가장 오래된 번호 또는 명시한 START_SEQ다. 누락 번호는 자동으로 건너뛰지 않는다.
- 기존 AIR-400 v2 모델과 전처리 함수를 import해 그대로 사용하며 학습하지 않는다. 모델은 프로세스 시작 시 한 번 로드한다.
- FFprobe로 포맷과 길이를 확인하고 합계 30±0.25초만 허용한다. FFmpeg로 재인코딩해 30초 MP4를 만들며 최대 0.25초의 끝 프레임 보정만 허용한다. 실제 촬영 연속성은 번호만으로 증명할 수 없으며 결과에 그 한계를 명시한다.
- 결과는 새로 정의한 `public.babycam_analysis_results`에 저장한다. 동봉 SQL은 사용자가 대상 프로젝트에서 실행할 신규 스키마다. 기존 테이블을 자동 변경하지 않는다.
- batch_id는 stream_id, 입력 번호, 모델/설정 서명으로 결정한다. 로컬 outbox를 먼저 원자 저장하고 중복 무시 upsert 성공 후에만 커서를 이동한다. DB 오류 때 재추론하지 않는다. 처리 실패는 제한된 재시도 후 unscored로 기록한다.
- 소스 세그먼트는 동일 prefix에서 덮어쓰지 않는 전제다. 번호가 초기화되거나 세션이 바뀌면 새 prefix/STREAM_ID/WORK_DIR를 사용한다. 같은 WORK_DIR 수집기 중복 실행은 OS 파일 잠금으로 거부한다.
- 결과 상태는 anomaly_candidate / below_threshold / unscored다. 마지막 상태는 점수·BPM·bool·파형을 null로 보낸다. 실패를 정상으로 표시하지 않는다.
- 결과 서버는 Supabase를 2초 간격 조회하고 로컬 브라우저에 /api/results와 기본 화면을 제공한다. 화면은 1초마다 캐시를 읽는다. 실패 시 이전 결과를 유지하되 연결 오류/마지막 성공 시간을 표시한다. 임상적 정상 또는 무호흡 확정 문구를 사용하지 않는다.
- SUPABASE_URL과 서버 전용 secret 또는 legacy service_role 키는 Python 프로세스의 .env에만 둔다. 프론트에는 전달하지 않는다. 서버는 loopback에만 바인딩하고 원격 서비스·사용자 로그인은 이번 범위에 포함하지 않는다.
- 검증: 누락/짧은 배치, 상태·문자열 bool, 입력 검증, 페이징·인증, 재시작·중복·업로드 실패, 실제 FFmpeg 결합, 실제 기존 모델 단일 배치, 브라우저 대기/갱신/오류 화면을 확인한다. 실제 Supabase 운영 연결은 사용자가 키를 채운 뒤에만 확인할 수 있다.
