# IDD 시계열 분류 구현 기준

사용자 요구사항을 구현 계약으로 사용한다. 원본은 읽기 전용으로 취급한다.

| 모듈 | 책임 | 검증 기준 |
|---|---|---|
| data | 실제 index와 ego CSV 검증, 공식 규칙으로 조건 라벨 생성 | 참가자/round/task 경로 일치, 주석 Alcohol 교차검증, 오류·제외 기록 |
| features | 좌표와 ns 시각으로 동일한 4개 특징 산출 | 직선·감속·곡선 해석값, 온라인/오프라인 일치, 단절 후 상태 초기화 |
| experiment | 참가자 분할, 정규화, Window, LSTM 학습·평가 | 분할 교집합 없음, train만 정규화, validation만 임계값·길이 선택 |
| inference | 차량별 좌표 스트림 → 점수/판단 보류 | 품질 불량·단절·ID 변경 후 이전 Window 사용 금지 |

구현 순서: 데이터 실사 → 공통 특징 및 테스트 → 분할·Window → 학습·평가 → 추론 및 재생 검증.

## 사전 결정

- 초기 주 실험은 experiment1(P 참가자) + no_task로 제한한다. 숫자 ID 집단은 음주 양성 데이터가 없어 집단 차이를 이용한 분류를 피하기 위함이다. 변경은 설정으로 명시한다.
- 공식 제외 참가자 목록과 시뮬레이터 이상 주석을 적용한다. 위험 상황 실패/충돌을 음주 라벨로 사용하지 않는다.
- 위치의 최근 11점에 3차 최소제곱 다항식을 맞춰 끝점에서 미분한다. 좌표 평활화와 미분이 한 연산에 포함된다. v,a,j는 같은 적합 궤적의 1·2·3차 미분이다.
- speed=||v||, acceleration=(v·a)/||v||, jerk=||j||, turn_rate=|vx ay-vy ax|/||v||². 거의 정지하면 acceleration=0, 0.5m/s 미만 turn_rate=0으로 정지 방향의 비정의를 처리한다. 입력 순서는 바꾸지 않는다.
- 10Hz 선형 리샘플링은 두 관측 사이에서만 수행한다. 출력은 오른쪽 관측이 들어온 뒤 생성하므로 최대 0.2초의 명시적 대기 지연이 있다. 미래 관측을 미리 읽거나 긴 단절을 잇지 않는다. 추가로 1초의 초기 평활화 이력이 필요하다.
- 3/5/10초는 30/50/100개 특징점이다. 첫 판단까지 약 3.9/5.9/10.9초 + 리샘플링 대기가 필요하다.
- 공정한 길이 비교를 위해 동일 참가자 분할과 동일한 Window 끝 시각을 사용한다. 세 길이 모두 100개 특징이 쌓인 시각부터 1초 간격으로 Window를 만든다. 실제 추론은 각 길이만큼 모이면 시작한다.
- validation에서 FPR≤5% 후보 중 recall 최대 임계값을 선택한다. 이 5%는 연구용 기본값이며 운영 합의나 보장치가 아니다. 같은 기준의 참가자 macro recall로 길이를 선택하고 동률이면 짧은 길이를 택한다. test는 선택에 사용하지 않는다.
- 참가자×음주 조건 평균 점수와 참가자별 지표를 별도로 낸다. 한 사람이 두 라벨을 가지므로 참가자 전체를 한 라벨로 합치지 않는다. 신뢰구간은 참가자 군집 bootstrap으로 산출한다.
- IDD 조건 분류 결과를 CCTV 음주 탐지 정확도로 해석하지 않는다. round/시나리오 교란, 좌표 잡음, 미터 스케일, 추적 불안정, 운영 경보율을 후속 실험에서 검증한다.

## 구현 스타일

특징·데이터·모델·지표·실험·추론·명령행을 기능별로 분리한다. 플러그인 레지스트리나 범용 학습 프레임워크를 도입하지 않는다. 개선 실험의 LSTM/GRU/TCN 선택은 명시적인 세 종류 매핑 함수 하나로 처리한다. 한국어 주석과 문서로 선택 이유와 단위를 설명하고 식별자는 Python 관례를 따른다. 테스트는 표준 unittest를 사용한다.
